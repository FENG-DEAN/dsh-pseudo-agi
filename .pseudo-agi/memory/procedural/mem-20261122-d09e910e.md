在 DSH/cordis 里，插件用 ctx.get(name) 读不到由兄弟插件 provide 的服务，会静默返回 undefined；必须用 ctx.inject([name], (scopedCtx) => {...}) 在依赖作用域内读。export const inject = [...] 是"插件必需依赖"声明（缺失则不加载插件），ctx.inject 则是"依赖就绪后回调"，两者都不等价于 ctx.get。

实证：pseudo-agi-panel 首次改用 ctx.get('credentials', false) 读 cookie secret，单测全绿（测试里 credentials 由同一 app 直接 provide，可见），但真机始终返回 undefined → 走放行分支，面板路由仍 200。本地对照实验证明这与加载顺序无关（credentials 先于/后于 panel 注册都返回 401）。换成 ctx.inject(['credentials'], cb) 后真机立即生效：无 cookie 的 GET /pseudo-agi/api/state 返回 401。

推论（未单独验证）：任何 DSH 插件跨层读取别层服务（credentials、webServer、agentPresets 等）时都应走 ctx.inject 作用域。
