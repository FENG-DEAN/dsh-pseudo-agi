在 DSH 插件里，工具执行的 `exec.agent` 类型是 `Agent`，不是 `Session`（定义见 `dsh-tools/src/contracts.ts` 的 `ToolExecutionInput.agent?: Agent`）。要拿会话信息必须取 `exec.agent.session`——`Agent` 上有 `readonly session: Session`。

踩坑过程：pseudo-agi-tools 的 guard 里调用 `ctx.sandboxPolicy.resolve({ session: exec.agent })`，resolve 内部读 `session.header.cwd`，而 Agent 没有 header，抛 TypeError。该异常被 `catch { return undefined }` 吞掉，于是表现为"没有策略可用"、一律放行，看起来像"插件没接上沙箱"，实际是"接错了对象还静默降级"。改成 `resolve({ session: exec.agent?.session })` 后立即生效。

可复用的教训：
1. 从 `exec` 取会话，用 `exec.agent?.session`。
2. 兜底的 `catch` 不应把可分辨的接线错误变成"功能缺失"；至少留一条可观测痕迹（本次靠临时诊断日志写 %TEMP% 才定位）。
3. 单测测不到这类错误，因为测试里 `modeOf` 是直接注入的假函数，绕过了真实的 Agent→Session 转换；必须真机验证。

真机双向验证：danger-full-access 下写入成功、read-only 下拒绝且文件未创建。
