把 @pseudo-agi/* 分发进 DSH profile 的可行组合（2026-11-22 实测，退出码 0）：

1. 六个包各自 pnpm pack 出 tarball。pnpm 会把 package.json 里的 workspace:^0.1.0 转成 ^0.1.0。
2. profile 的 package.json 里，bundle 用 file: 指向 tarball；同时必须写 pnpm.overrides，把 @pseudo-agi/memory/tools/scaffold/governance/panel 各自 file: 到对应 tarball——否则 bundle 的 ^0.1.0 会去公共 registry 找私有包并失败。
3. .npmrc 必须写 auto-install-peers=false 与 strict-peer-dependencies=false：插件把 @deepseek-ai/* 声明为 peer，而那些包由宿主运行时提供、不在 registry 上，pnpm 自动安装 peer 必然失败。
4. 验证点：node_modules/@pseudo-agi/ 下五个层包齐全、bundle/cordis.patch.yml 在位、各包 lib/index.js 与 panel/client.js 在位、patch 引用的五个插件名都能解析。

另外 bundle 本身也有过时问题需要维护：它曾引用已删除的 @pseudo-agi/controller，且漏了 panel 行；bundle 的 patch 里 workspaceRoot: . 相对宿主 cwd，安装后必须在 profile 覆盖为绝对路径。
