pseudo-agi 的冲突检测（memory_recall 返回 conflicts）判定条件共三项，缺一不报：同一层、共享 ≥2 个标签、标题重叠 ≥2 个词。它只报告，不过滤、不重排、不自动裁决——"哪条仍然成立"是语义判断，归读者。

这个阈值是两轮真机误报逼出来的，不是拍脑袋定的：
1. 初版「共享 ≥1 标签 + 标题重叠 ≥2 词」在真机上报出 2 对全误报。第一对是两个不同事件（面板鉴权生效 vs 五层验收）只因共享 `真机` 一个标签就被报——单标签只说明话题相邻，不说明矛盾。
2. 收紧到「≥2 标签」后误报剩 1 对：semantic 的设计原则与 episodic 的实现记录。两者跨层，而不同层是"什么成立"与"发生了什么"，构造上不可能互相矛盾，于是加「同层」约束。
3. 收紧后真实库 5 组查询只剩 1 对误报（两个不同阶段的验收记录）。到此主动停止调参：再严会漏真冲突，而误报代价只是多看一眼。

验证技巧：改完 memory 包不必重启宿主，直接 import 编译后的 lib/store.js 对真实记忆库跑 recall 即可看到 conflicts，比反复重启快。
