DSH 的文件策略分工（源自 app.asar 内包 README 与源码，非推断）：

1. ctx.sandbox / dsh-sandbox 是"进程沙箱"：让子进程及其派生物在 read-only / workspace-write / danger-full-access 下运行，由 bash/pwsh 消费。它不表达网络、进程、系统调用限制。
2. dsh-fs-sandbox 是 ctx.fs 的围栏后端，覆盖 writeText / editText / patchText / deleteFile / moveFile 五个写操作；读取不受限。
3. dsh-sandbox-policy 是唯一策略归属：resolve({session, mode}) 同步返回 { mode, workspaceRoot, additionalWritableRoots?, sessionId? }，优先级为 显式授权 > 会话最后一条 sandbox/mode 事件 > 部署默认（默认 read-only）。会话工作区来自 SessionHeader.cwd。
4. 因此：DSH 自带工具（write/edit 走 ctx.fs、pwsh 走 ctx.shell）自动受策略约束；而插件自己实现的写盘工具（如 pseudo-agi 的 controlled_write）不会自动受约束，必须自己 inject sandboxPolicy 并在守卫里调 resolve，否则就是策略的后门。
5. 读该服务必须用 ctx.inject(['sandboxPolicy'], cb) 作用域，ctx.get 在插件自身 ctx 上会返回 undefined（见 mem-20261122-d09e910e）。
